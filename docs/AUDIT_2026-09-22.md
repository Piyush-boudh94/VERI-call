# Audit — 2026-09-22

*An outside-eye audit of VeriCall: what the project set out to be, what it is
now, and what breaks it. Commissioned as a standing review, not a reaction to a
specific failure. Scope is VeriCall only — the T_WMamba video merge was treated
as out of scope (see Open Questions 1).*

**Method, so the reach of this document is clear.** Intent was reconstructed
from `CLAUDE.md`, `voice.md`, `docs/PLAN.md`, `docs/VERICALL_V4.md`,
`docs/PRODUCTION_READINESS.md`, `docs/RESULTS.md` and 94 commits, *before* any
source file was read. Every claim below is either cited to `file:line` or to a
command run during the audit. Nothing here is a re-derivation of a number that
already exists in `docs/RESULTS.md`; where this document quotes one, it quotes
it.

**What could NOT be verified, and why.** The pod was gone at audit time
(`./scripts/pod.sh name` → *no running `wmamba-dev` pod*), pod scratch held only
`in_the_wild`, and the head node has no GPU. So nothing requiring the GPU or a
staged corpus was re-measured — including the one experiment this audit most
wants (F2 below). Those items are marked **unmeasured**, never estimated.

**What was run.**

```
python3 -m pytest tests/ -q -p no:cacheprovider   # 357 passed, 2 skipped, 15 s
python3 run_local.py --check                      # all ok; 1 warning (no CUDA here)
```

## 1. Plan reconstruction, and the drift

### The goal as first conceived

SIH 2026 PS 26104 — real-time detection **and prevention** of voice-cloning
impersonation on live calls. Multilingual across Indian languages, privacy-
preserving, near-real-time, integrable by banks and telcos.

### The goal as the code now expresses it

A streaming, calibrated, four-branch LLR accumulator with a tiered prevention
policy, whose measured strength is in-domain ASVspoof and whose measured
weakness is every other domain.

**The drift, stated plainly:** *detection* has quietly come to mean **"well-
calibrated evidence accumulation,"** which this project has genuinely solved,
while **"detects cloned speech in Indian-language telephony,"** which it has
not, is measured honestly and deferred. That is a defensible engineering
position and it is not the problem statement. It is recorded here because a
drift everyone can see is not the dangerous kind — a drift nobody has written
down is.

To the project's credit, this was never concealed: `CLAUDE.md` §3 instructs
readers to quote the cross-corpus number rather than 2.48%, and the rule exists
*because* someone anticipated this exact temptation.

### Reconciliation against the two prior artifacts

**The v4 roadmap — not found as described.** No document in this repo has
7 phases across 2 tracks with demo checkpoints and a red-team gate. A grep for
`Track A|Track B|two tracks|Phase 5|Phase 6|Phase 7|red-team gate|demo
checkpoint` over every `.md` returns one unrelated hit
(`docs/BENCHMARKS.md:82`). What exists is `docs/VERICALL_V4.md`, a **whitepaper**
of 11 sections, and `docs/PLAN.md`, a 5-item critical path with a 10-day
sequence, written 2026-09-05 and now largely executed. Either that roadmap was
never committed, or "v4" means the whitepaper and the 7-phase structure belongs
to something else. **Unresolved — Open Question 7.**

**Section 9 — found and reconciled.** `docs/PRODUCTION_READINESS.md`. Note it
carries **nine** failure modes, not eight: FM-0 was added *after* the draft, by
conflict C14, because measurement found the dominant failure mode missing from

## 2. ML findings

Severity is assigned against **detection performance in the deployment domain**,
not against pipeline completeness. A pipeline that runs end to end but does not
separate cloned from genuine speech at a usable error rate is a Critical
finding, not a working prototype.

### F1 — Critical — detection is not at a usable error rate on the target domain

| Evaluation | Result |
|---|---|
| Hindi (IndicSynth), 5% FP budget | **13.9%** attack recall (RTCFake head); **5.3%** (ASVspoof head — chance) |
| Mandarin (RTCFake zh) | 33.41% EER, against a 41.43% trivial-cue baseline |
| In-the-Wild | 22.48% EER (per-window) |
| Replay (EchoFake) | 33.68% best |
| WaveFake, unseen vocoders | 30.29% |
| ASVspoof dev / A+A2 subset table | 2.48% / 1.46% — **in-domain only** |

Sources: `CLAUDE.md` §3 and §8B; `docs/RESULTS.md` §13, §20, §21, §24;
`docs/indic_hindi.json`.

The product targets Indian-language telephony. On its target languages the
deployed profile is at or near chance. The usable numbers are all in-domain
ASVspoof, and `calib/provenance.json` confirms the shipped heads are
`branch_A_seed0.pt` / `branch_A2_seed0.pt` — the plain ASVspoof baseline.

**Why this is not an engineering finding.** Six independent measured attempts
say modelling will not close it: corpus mixing, RTCFake-only training,
domain-adversarial training, OC-Softmax, RawBoost and SSL layer selection (§20,
§22, §24). Every one was neutral or worse out of domain. The project's own
diagnosis — an Indian-language **bona fide** corpus paired to IndicSynth's own
source recordings — is correct, and its refusal to borrow bona fide from an
unrelated corpus is also correct: that would let a detector separate the classes
by recording condition and would measure the pairing, not the model.

**Recommended, not applied.** This is a data-acquisition decision or a
scope-narrowing decision. Both are legitimate; neither is the assistant's to
make.

### F2 — High — training/serving preprocessing skew on the live path

Every training, calibration and evaluation sample passes `load_audio(trim=True)`
→ VAD-trim (`vericall/data/audio_io.py:53-66`), at `scripts/extract_features.py:221`,
`scripts/fit_calibration.py:161` and `scripts/end_to_end.py:70`.

The live path does not. `serving/app.py:1132-1134` converts int16 PCM straight
to float and calls `session.push_audio` (`serving/session.py:60-62`) →
`chunker.push`. **No trim.**

The rule "VAD-trim before windowing, always" is asserted as enforced in code —
`CLAUDE.md:181` and `:225`, `docs/VERICALL_V4.md:629`, `docs/DATASETS.md:190-193`.
It is enforced on the **file** path only.

Consequences:

- The headline end-to-end result — 40/40 spoof alerted, 0/40 bona fide,
  −50.23 nats — was measured on **silence-trimmed clips streamed as if live**.
  It does not transfer unchanged to a real microphone or WebRTC call.
- The Platt mappings were fitted on trimmed crops, so LLRs on partially-silent
  live windows are outside the distribution the calibration describes.

Partial mitigation, and it is real: `quality_discount()` returns 0.0 below
quality 0.15 (`risk/aggregation.py:129`), so near-silent windows contribute no
evidence. Windows mixing speech and silence still score and still bank evidence.

**Magnitude is unmeasured.** Note the direction is not the obvious one: the
model never saw the leading-silence cue in training — trimming removed it — so
this is distribution shift and miscalibration, not shortcut exploitation. It
could be small.

**Flagged, not applied** — any change here alters served scores. The cheapest
resolution is measurement, not a patch: re-run `scripts/end_to_end.py` with
trimming disabled and compare per-call nats against the recorded run. Blocked on
the pod.

### F3 — High — the FM-0 runtime mitigation is not wired in

`DomainGuard` detects exactly the deployment-breaking case and is validated
doing so (`docs/domain_guard_validation.json`: clean on ASVspoof dev bona fide,
trips on RTCFake-en bona fide, correctly naming the A/A2 sign disagreement as
the signature of one branch inverting under domain shift).

The gateway never builds one — `serving/app.py:442`, `fusion/engine.py:147`.

So the dominant, measured failure mode has a working tripwire that is switched
off in production. A tenant outside the calibration domain receives confident
nonsense with no signal that anything is wrong — the precise scenario §13
documented and §17 built the guard for.

**Flagged, not applied**: wiring it changes served verdicts, because
`calibration_suspect` would begin firing. Recommended shape — construct with the
`calib/` reference, surface in `/health` and in the history row, alert-only
before it is allowed to influence a tier.

### F4 — Medium — the held-out OOD set has become a model-selection set

`CLAUDE.md:224`: *cross-domain eval sets are touched once, at the end.* In
practice In-the-Wild has now scored four training configurations
(`docs/RESULTS.md:1555-1585`) and the §20 family is on its sixth confirmation.

The repo names the hazard itself (`docs/RESULTS.md:1267-1276`: *"the held-out set
must then be something else again, or the measurement becomes circular"*), which
is why this is Medium and not High. The inflation is probably small — the
baseline was already the deployed model and simply won — but **22.48% is no
longer an untouched held-out number**, and the decision to keep the ASVspoof
baseline is now partly justified by a set that was supposed to be virgin.

**Recommended:** freeze In-the-Wild now and iterate against CodecFake or
EchoFake instead. Which set becomes the frozen one is a judgment call.

### F5 — Medium — the real-corpus leakage guards do not run in the default suite

The two strongest guards — official-protocol match and train/eval attack
disjointness on actual ASVspoof — are `skipif`'d when corpora are absent
(`tests/test_splits.py:188-206`), and absent is the normal state: scratch has
been wiped repeatedly and is wiped now. Measured this session:

```
SKIPPED [1] tests/test_splits.py:194: corpora live on ephemeral pod scratch
SKIPPED [1] tests/test_splits.py:205: corpora live on ephemeral pod scratch
```

"Leakage guards are assertions… a violation fails the build" (`CLAUDE.md` §6) is
therefore true only inside the pod with corpora staged. Everywhere else the
guards run against synthetic fixtures — which are good fixtures, and are not the
corpus.

**Recommended:** freeze a small protocol digest (speaker and attack ID sets, a
few KB, NFS-resident) so the real-protocol assertions run on the head node too.

### F6 — Medium — speaker-disjointness is unverifiable for RTCFake

`data/splits.py:54-56` exempts `RTCFake_unknown` from the speaker guard because
the corpus publishes no speaker labels, and `tests/test_splits.py:300-310` pins
that this is an **exemption, not a pass** — a guard comparing sentinel IDs would
have reported a flattering disjointness that means nothing.

This is the right handling. The residual limit is real: RTCFake is the corpus
behind the `calib_rtc` profile, so its 22.93% carries no speaker-generalisation
guarantee. **Recommended:** carry that caveat in the results table itself, not
only in the splitter.

### F7 — Medium — no process for drift against an improving adversary

FM-6 is unimplemented: no replay buffer, no continual learning, no scheduled
re-test. All corpora are fixed releases and no 2026 commercial cloning tool has
been evaluated. Cloning tools update continuously; a frozen corpus set ages
silently and a hardening claim from an earlier snapshot goes stale without
anyone editing a file.

**Recommended:** a quarterly *manual* re-test protocol against current tool
versions. Cheaper than continual learning and it satisfies what FM-6 is for.

### F8 — Low — min-tDCF is not computed

EER (`fusion/calibration.py:30`, with tie collapsing and interpolation), Cllr
(`:78`) and minCllr (`:95`) all are, plus bootstrap CIs resampling utterances and
paired FPR/FNR throughout. ASVspoof's secondary standard metric is the only
thing missing, and Branch C (ECAPA) could supply the ASV side it needs.

This is a completeness gap, not a correctness one. The metric discipline here is
above the bar, not below it.

### Checked and clean — no finding

Recorded so a later audit need not re-derive them.

- **Preprocessing leakage.** No `fit_transform`, no scaler fitted on a full
  dataset. Platt fitting happens on a speaker-disjoint `calib` fold
  (`data/splits.py:103-128`), carved out by speaker precisely so the operating
  point is not fitted on the voices that drove early stopping.
- **Group leakage.** Source-utterance groups never span folds; WaveFake vocoder
  resyntheses of one sentence share a fold; EchoFake speakers are assigned
  whole; CodecFake is speaker-disjoint by construction.
- **Duplicate leakage.** Caught and tested, after EchoFake shipped 1,986
  duplicate `utt_id`s that silently corrupted a split.
- **Channel/codec confound.** Augmentation is assigned by crop index
  (`scripts/extract_features.py:231`), identical for every clip and entirely
  independent of the label, so classes are channel-matched by construction. The
  project also *refuses* cross-corpus bona fide borrowing, which is the
  larger-scale version of the same trap.
- **Streaming/truncation match.** Training crops are 1.0 s
  (`scripts/extract_features.py:66`); the serving fast lane is a 1.0 s window on
  a 0.5 s hop (`audio/chunker.py:37-40`). The model is trained on what it is
  served.
- **Class imbalance.** Prior-weighted loss (`scripts/train.py:94-95`).
- **Naive baseline.** Silence-duration baselines measured **per corpus**
  (`scripts/audit_silence.py`), with an explicit rule against quoting one
  corpus's baseline at another's model.
- **Overfitting/underfitting controls.** Dropout 0.1, `weight_decay=1e-4`,
  dev-EER early stopping, 3 seeds with spread reported, an overfit-100 sanity
  check and a duration-baseline gate in the trainer.
- **Reproducibility.** Seeds fixed across init, shuffling and augmentation;
  `stable_bucket` uses SHA-256 rather than Python's per-process-randomised
  `hash()`.
- **Per-language breakdown.** Reported rather than aggregated away.
- **LLM/agent layer.** None exists, so prompt injection, sampling
  non-determinism and per-request LLM cost are all N/A.

   repo references it, `~/research` is a separate project, and its own record
   states audio is entirely out of scope there. Confirm, or the audit re-scopes.

   in the repo. Without one, *"does this work"* has no answer that can be
   checked. What is shippable for a 30–50 user pilot, and separately for an
   Indian-language call?
3. **F1 is a data decision.** Acquire or commission Indian-language bona fide
   audio paired to IndicSynth's sources, or narrow the pilot's claimed scope to
   the domains where the numbers hold. Both are honest; the second is free.
4. **Wire `DomainGuard`?** It changes served output.
5. **Which eval set becomes the frozen one**, now that In-the-Wild has been used
   four times?
6. **Deployment mode.** `voice.md` §1 flags that Mode B (server-side) was assumed
   and never confirmed. It decides where the F2 fix belongs — gateway or client.
7. **Where is the 7-phase / 2-track v4 roadmap?** Not in this repo.
8. **No git remote.** 94 commits exist only on a shared, near-full NFS volume.
